# onemoreday.fun

Небольшой веб-сервис: вводите дату рождения — и видите, сколько уже прожили,
с точностью до секунды. Дальше пожелание на день и QR-код, чтобы поделиться.

**Живёт здесь: [onemoreday.fun](https://onemoreday.fun)**

---

## Стек

**Бэкенд** — Python 3, стандартная библиотека. Никаких фреймворков
и сторонних зависимостей нет, поэтому в проекте нет `requirements.txt`.

**Фронтенд** — Vue 3, подключённый напрямую с CDN. Без сборки, без npm,
без `node_modules`.

**Инфраструктура** — VPS Ubuntu 24.04, nginx как reverse proxy, systemd,
HTTPS от Let's Encrypt.

## Как это устроено

```
браузер
   │
   ▼
 nginx  ──── / , /style.css , /app.js ────►  статика из frontend/
   │
   └──────── /api/ ──────────────────────►  Python на 127.0.0.1:8000
```

nginx смотрит на путь запроса. Всё, что начинается с `/api/`, он передаёт
Python-бэкенду на локальный порт; остальное отдаёт файлом из папки
`frontend/`. Сам бэкенд слушает только `127.0.0.1` — из интернета
достучаться до него напрямую нельзя.

### Бэкенд

| Файл | Что делает |
|---|---|
| `backend/age_calculator.py` | Чистая логика: разбор даты и расчёт возраста. Ничего про HTTP — такую функцию легко тестировать |
| `backend/server.py` | HTTP-слой: `ThreadingHTTPServer`, один эндпоинт, JSON, обработка ошибок |

Единственный эндпоинт:

```
GET /api/age?birthdate=2000-01-01
```

```json
{"years": 26, "months": 7, "days": 4, "hours": 15, "minutes": 56, "seconds": 31}
```

Ответ — это **разбивка**, а не перевод одного срока в разные единицы:
каждая следующая единица считается как остаток после предыдущей.

Вся валидация даты — на стороне сервера. Клиент только показывает то,
что ему ответили: существует ли такая дата, не в будущем ли она и не слишком
ли она давняя, решает бэкенд.

Ошибки приходят в том же формате, со статусом 400:

```json
{"error": "Дата рождения не может быть в будущем"}
```

### Фронтенд

| Файл | Что делает |
|---|---|
| `frontend/index.html` | Разметка трёх экранов + мета-теги Open Graph для превью ссылки в мессенджерах |
| `frontend/app.js` | Всё состояние и логика: ввод, запрос к бэкенду, QR-код, «Поделиться» |
| `frontend/style.css` | Оформление |

Три экрана внутри одной карточки: **форма → пожелание → QR-код**.

Что сделано руками (готовые компоненты не подключены):

- **поле даты из восьми клеток** — автопереход к следующей, `Backspace`
  возвращает к предыдущей, стрелки двигают курсор, вставка даты из буфера
  раскладывается по клеткам сама;
- **русские числительные** — «31 год», «33 года», «12 278 дней»;
- **таймаут запроса** — через `AbortController`, чтобы кнопка не висела
  в «Считаю…» бесконечно, если сервер молчит;
- **«Поделиться»** — системное меню через Web Share API на телефоне,
  с запасным вариантом через буфер обмена на компьютере;
- **QR-код** — рисуется на клиенте, и только в момент перехода на последний
  экран.

## Запуск у себя

Ставить нечего — зависимостей нет. Нужен только Python 3.10 или новее
(в коде используется синтаксис `datetime | None`).

**1. Бэкенд:**

```bash
cd backend
python3 server.py
```

Поднимется на `http://127.0.0.1:8000`. Проверить:

```bash
curl "http://127.0.0.1:8000/api/age?birthdate=2000-01-01"
```

**2. Фронтенд.** В продакшене фронт и бэк живут на одном домене, поэтому
адрес бэкенда в коде относительный. Локально nginx нет, и его надо временно
заменить на полный — в `frontend/app.js`:

```js
const BACKEND_URL = "http://localhost:8000/api/age";
```

После этого `frontend/index.html` можно открыть двойным щелчком. Запросы
с файла на localhost сервер разрешает — CORS-заголовки в `server.py` уже
проставлены.

> Перед выкладкой не забыть вернуть `const BACKEND_URL = "/api/age";`

## Чего здесь намеренно нет

Проект маленький, и часть привычных вещей не взята сознательно:

- **базы данных** — хранить нечего, введённые даты никуда не сохраняются;
- **Docker** — обычной службы systemd достаточно;
- **сборки фронтенда** (npm, webpack, Vite) — Vue подключён с CDN;
- **отдельного WSGI-сервера** (gunicorn, uvicorn) — встроенного
  `ThreadingHTTPServer` за nginx для такой нагрузки хватает.

Каждый пункт — решение под конкретную задачу и нагрузку, а не пропуск.
Если сервис вырастет, к этому списку придётся вернуться.
