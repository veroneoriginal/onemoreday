# onemoreday.fun

Небольшой сайт, который поддерживает, когда тяжело. На первом экране
два пути:

- **«Получить поддержку»** — тёплая фраза на сегодня, каждый раз случайная;
- **«Посчитать важную дату»** — вводите дату события, которого ждёте,
  и видите, сколько до него осталось, с точностью до секунды.

Оба пути заканчиваются QR-кодом и кнопкой «Поделиться».

**Живёт здесь: [onemoreday.fun](https://onemoreday.fun)**

---

## Стек

**Бэкенд** — Python 3, стандартная библиотека. Никаких фреймворков
и сторонних зависимостей нет, поэтому в проекте нет `requirements.txt`.

**Фронтенд** — React, сборка Vite. Зависимости ставятся через npm
в папке `frontend/`.

**Инфраструктура** — VPS Ubuntu 24.04, nginx как reverse proxy, systemd,
HTTPS от Let's Encrypt.

## Как это устроено

```
браузер
   │
   ▼
 nginx  ──── / , /style.css , /app.js ────►  статика из frontend/
   │
   └──────── /api/ ──────────────────────►  Python на 127.0.0.1:8000
```

nginx смотрит на путь запроса. Всё, что начинается с `/api/`, он передаёт
Python-бэкенду на локальный порт; остальное отдаёт файлом из папки
`frontend/`. Сам бэкенд слушает только `127.0.0.1` — из интернета
достучаться до него напрямую нельзя.

Картинка выше — то, как сайт собран на сервере сейчас. В репозитории то же
деление делает `docker/docker_compose.yaml`: снаружи только nginx, `/api/` уходит
в контейнер бэкенда, страница — из контейнера фронтенда.

### Бэкенд

| Файл | Что делает |
|---|---|
| `backend/age_calculator.py` | Чистая логика: разбор даты и расчёт времени до события. Ничего про HTTP — такие функции легко тестировать |
| `backend/server.py` | HTTP-слой: `ThreadingHTTPServer`, один эндпоинт, JSON, обработка ошибок |
| `docker/Dockerfile` | Один файл на три контейнера: backend, frontend, nginx |
| `docker/docker_compose.yaml` | Три сервиса в одной сети. Снаружи открыт только nginx |
| `docker/nginx.conf` | Страница с контейнера frontend, `/api/` — на backend |

Единственный эндпоинт — сколько осталось до события:

```
GET /api/until?date=2028-07-17
```

```json
{"years": 1, "months": 9, "days": 24, "hours": 9, "minutes": 29, "seconds": 45, "total_days": 664}
```

Ответ — это **разбивка**, а не перевод одного срока в разные единицы:
каждая следующая единица считается как остаток после предыдущей.
Время события не спрашиваем, поэтому отсчёт идёт до полуночи этого дня.
`total_days` — отдельно, сколько календарных дней осталось (завтра — 1).

Вся валидация даты — на стороне сервера. Клиент только показывает то,
что ему ответили: существует ли такая дата, в будущем ли она и не слишком
ли она далёкая, решает бэкенд.

Ошибки приходят в том же формате, со статусом 400:

```json
{"error": "Выберите дату в будущем — хотя бы завтра"}
```

### Фронтенд

| Файл | Что делает |
|---|---|
| `frontend/index.html` | Оболочка страницы и мета-теги Open Graph для превью ссылки в мессенджерах |
| `frontend/src/main.jsx` | Точка входа: монтирует React в `#root` и подключает оформление |
| `frontend/src/App.jsx` | Экраны, ввод даты, список пожеланий, QR-код и «Поделиться» |
| `frontend/style.css` | Оформление |

Одна страница, экраны переключаются внутри одной карточки:

```
                 ┌─► пожелание на день ─────────────┐
приветствие ─────┤                                  ├─► QR-код
                 └─► ввод даты ─► сколько осталось ─┘
```

Пожелание собирается из постоянной фразы «Сегодня к сумме Вашей жизни
добавляется ещё один день» и случайной из списка `WISHES` в `App.jsx`.

Что сделано руками (готовые компоненты не подключены):

- **поле даты из восьми клеток** — автопереход к следующей, `Backspace`
  возвращает к предыдущей, стрелки двигают курсор, вставка даты из буфера
  раскладывается по клеткам сама;
- **русские числительные** — «31 год», «33 года», «12 278 дней»;
- **таймаут запроса** — через `AbortController`, чтобы кнопка не висела
  в «Считаю…» бесконечно, если сервер молчит;
- **«Поделиться»** — системное меню через Web Share API на телефоне,
  с запасным вариантом через буфер обмена на компьютере;
- **QR-код** — рисуется на клиенте, и только в момент перехода на последний
  экран.

## Запуск у себя

Бэкенду зависимости не нужны: хватает Python 3.10 или новее
(в коде используется синтаксис `datetime | None`).
Фронтенду нужен Node.js — зависимости ставятся через `npm install`.

**1. Бэкенд:**

```bash
cd backend
python3 server.py
```

Поднимется на `http://127.0.0.1:8000`. Проверить:

```bash
curl "http://127.0.0.1:8000/api/until?date=2028-07-17"
```

**2. Фронтенд:**

```bash
cd frontend
npm install
npm run dev
```

Vite откроет страницу на `http://127.0.0.1:5173`. Кнопка «Посчитать»
отправляет `GET /api/until?date=...` на этот же адрес. Vite пересылает
`/api` на `http://127.0.0.1:8000`, поэтому бэкенд должен быть уже запущен.

**3. Три контейнера:**

Образы ещё не существуют, пока их не собрать. Все три берутся из одного
`docker/Dockerfile`: команда выбирает цель и кладёт её в свой образ.

```bash
make start
make down
```

`make start` собирает три образа и поднимает контейнеры. Сайт откроется на
`http://127.0.0.1:8080`.
Порты бэкенда и фронтенда наружу не публикуются.
