# Выкладка onemoreday.fun

Живой список. Подробности появляются по мере того, как доходим до шага.
Команды на сервере выполняешь ты, я говорю, что именно сделать и как проверить.

Прод собираем контейнерами из репозитория: три образа (backend, frontend, nginx) через `make start`.
Снаружи у текущего compose открыт только порт 8080, без HTTPS. Домен подключаем тем же nginx из контейнера: сначала порт 80, потом сертификат на 443. Второй nginx на сервере не ставим.

## Уже готово в коде

Менять приложение, чтобы начать выкладку, не нужно.

- Фронтенд ходит на `/api/until` того же хоста, с которого открыта страница. На сервере этот путь заберёт nginx.
- В QR-код и «Поделиться» зашит `https://onemoreday.fun`.
- Бэкенд в контейнере слушает порт 8000 внутри сети Docker. Наружу этот порт не публикуется. Снаружи открыт nginx.
- Секретов, базы и файла с настройками нет.

Статика для прода — это результат `npm run build`, каталог `frontend/dist`. Исходники из `frontend/src` nginx не отдаёт.

Команды этого шага — на своём компьютере, не на сервере.

Секретная половина осталась в `~/.ssh/id_ed25519`, публичная — в `~/.ssh/id_ed25519.pub`.

Скопировать публичные ключи на сервер. Флаг убирает молчаливую паузу перед запросом пароля. Пароль root спросился один раз. `ssh-copy-id` нашёл на компьютере три публичных ключа и добавил все три:

Проверка, уже без пароля root:


`--no-build` значит «не собирать повторно»: образы только что собраны отдельными командами. Compose берёт их по именам из `docker/docker_compose.yaml`.

## Шаг 7. Домен на тот же nginx

Отдельный nginx на сервере не ставим. Сайт уже раздаёт nginx из контейнера. Сейчас он опубликован на порту 8080. Домен приходит на порт 80, поэтому в `docker/docker_compose.yaml` у сервиса nginx строка порта меняется с `"8080:80"` на `"80:80"`.

- [x] Снаружи открыт только `8080` (`docker-proxy`). Порты `80` и `443` свободны. `curl http://127.0.0.1` пустой, потому что на порту 80 ещё никто не слушает.

На сервере, в `/opt/onemoreday`, заменить порт в файле и показать строку:

```bash
sed -i 's/8080:80/80:80/' docker/docker_compose.yaml
grep -n "80:80" docker/docker_compose.yaml
```

Применить без повторной сборки:

```bash
docker compose -f docker/docker_compose.yaml up -d --no-build
```

Проверка на сервере:

```bash
curl -sI http://127.0.0.1
```

- [x] В `docker/docker_compose.yaml` порт nginx заменён на `"80:80"`. Контейнер перезапущен. `curl -sI http://127.0.0.1` на сервере даёт `HTTP/1.1 200`.
- [x] `ufw` на сервере выключен (`Status: inactive`). Порт 80 он не закрывает.
- [x] Снаружи `http://onemoreday.fun` отвечает `HTTP/1.1 200`, сервер `nginx/1.27.5`.

## Шаг 8. Сертификат

Сертификат Let's Encrypt включает `https://` для `onemoreday.fun` и `www.onemoreday.fun`. Его получает `certbot` на сервере: на минуту занимает порт 80, доказывает, что домен наш, и сохраняет файлы сертификата.

```bash
apt install -y certbot
```

- [x] `certbot` установлен. Каталог при установке не важен.

- [x] Почта для писем Let's Encrypt: `veronikanizovaya@gmail.com`.

Выпуск. Nginx на минуту останавливается, чтобы `certbot` занял порт 80. Третью команду выполнить даже если вторая закончилась ошибкой: она снова включает сайт.

```bash
docker stop onemoreday-nginx-1
certbot certonly --standalone -d onemoreday.fun -d www.onemoreday.fun --agree-tos -m veronikanizovaya@gmail.com --non-interactive
docker start onemoreday-nginx-1
```

- [x] Сертификат получен. Файлы: `/etc/letsencrypt/live/onemoreday.fun/fullchain.pem` и `privkey.pem`. Срок до 2027-02-17. `docker start onemoreday-nginx-1` после этого выполнился, сайт снова на `http://`.

Строка `docker: command not found` была из-за лишних символов при вставке. Повторный `docker start` контейнер включил.

## Шаг 9. Подключить сертификат к nginx

Остановка nginx была нужна один раз: так `certbot` занял порт 80 и получил первый сертификат.

`docker/nginx.conf` остаётся для локального `make start`: там нет сертификата, только порт 80. Если подставить в него пути Let's Encrypt, локальный запуск сломается. Поэтому для сервера отдельный `docker/nginx.prod.conf`: порт 80 уводит на https, порт 443 показывает сертификат. В compose он монтируется поверх конфига из образа, туда же монтируется `/etc/letsencrypt`. Образ заново не собирается.

Вставка целиком через `cat << EOF` не прошла: терминал остался на приглашении `>`. Ctrl+C вернул обычное приглашение. Файлы той вставкой не перезаписались.

- [x] `docker/nginx.prod.conf` на сервере записан и проверен через `cat`.

- [x] `docker/docker_compose.yaml` на сервере: порты `80` и `443`, тома `./nginx.prod.conf` и `/etc/letsencrypt`.

Применить без сборки и проверить сертификат:

```bash
docker compose -f docker/docker_compose.yaml up -d --no-build
curl -sI https://onemoreday.fun
```

- [x] `https://onemoreday.fun` открывается в браузере.
